## Long-term data behavior
- **Refresh policy**: No scheduled refresh. Feed, article, rooms read live from ctx.db on every open; Supabase session restores from browser storage.
- **Growth**: User posts, comments/replies, votes, and rooms persist in ctx.db and grow with use.
- **Identity**: `profiles` table keyed by Supabase auth uid (username unique case-insensitively). Posts/comments store `author_id` + `author_username`; the legacy `author` display column holds the username for member content and the original display name for starter posts (author_id null). Usernames also go into Supabase auth user metadata (`data.username` at signup, PUT /auth/v1/user on set/change). Email addresses are never stored in ctx.db and never rendered in the UI.
- **Admin**: There is no first-account owner rule anymore. The admin is whichever profile holds the username `admin` (case-insensitive); `profileOut.isOwner` is derived from that username. `setUsername` rejects taking or changing to `admin` when a different account already holds it. The `profiles.is_owner` column is kept in sync (1 only for the admin username) but authorization derives from the username.
- **Deletion**: `deletePost`/`deleteComment` take the caller's Supabase uid, load the caller's profile, and allow the delete only when (a) the caller's username is admin, or (b) the item's `author_id` equals the caller uid AND its `author_username` equals the caller's username (case-insensitive). Anything else throws "Only admin can delete any post. You can only delete posts with your username on them." Deleting a post removes all its replies. Delete buttons render only when the same check passes client-side, behind an inline "Yes, delete / Cancel" confirm that repeats the rule sentence.
- **FAQ / Wiki**: Static client content in `client/src/FaqWiki.tsx` (no server rows). FAQ: 14 Q&As in 6 groups, client-side search, per-question link into a Wiki page. Wiki: 8 pages with sidebar + search, content scoped to Muse AI / Meta Glasses / Meta AI app / Meta integrations in Learn/Build/Help/Show/News terms. Images are AI-generated illustrations in the FED palette, generated at build time into `client/src/assets/` (faq-hero.webp, wiki-hero.webp, wiki-*.webp x8) and imported by the client; no hotlinks.
- **No bulk export**: The ZIP download (nav button, hero card, client ZIP builder, and the `getExportData` action) was removed entirely on 2026-11-25 at the owner's order. There is no endpoint that returns all site data at once.
- **Ordering**: Feed newest first by post date then id; comments oldest first (thread order); rooms newest first.
- **Time semantics**: Post/comment dates are calendar dates (YYYY-MM-DD) as in the seed; new posts/comments use the viewer's current date at submit time.

## Rejected approaches
- **Tried**: Rebuilding the static multi-page HTML site inside the artifact
  **Why rejected**: The request is explicitly a backended space; votes, comments, new posts, and rooms must persist server-side — a static copy cannot do that.
- **Tried**: Server-side Supabase proxy actions
  **Why rejected**: Supabase publishable-key auth is designed for direct browser calls; proxying adds latency and would handle passwords on the artifact server for no benefit.
